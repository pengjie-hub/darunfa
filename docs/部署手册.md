## 0. 部署后的架构

```
浏览器 / 面试官
      │  http(s)://域名
      ▼
宿主机 Nginx（80/443，Let's Encrypt 证书）
      │  proxy_pass http://127.0.0.1:8080
      ▼
Docker: app 容器（Spring Boot 4 fat jar）
      │  内含 Vue /app/ + 旧 /admin.html + /login.html
      │  JDBC
      ▼
Docker: mysql 容器（MySQL 8.0，utf8mb4_0900_ai_ci）
```

- `app` 容器只发布到宿主机 `127.0.0.1:8080`，不直接暴露公网。
- `mysql` 容器不映射端口，只在 Compose 内网可达。
- 前端 `VITE_API_BASE=/api`，与后端同域，不需要 CORS。
- Vue 后台是 hash 路由：`/app/#/login`、`/app/#/dashboard`，刷新不会 404。

## Stage 1 · 买服务器与域名

### 1.1 服务器

推荐：**阿里云轻量应用服务器，韩国/香港等境外节点，2 核 2G，40G SSD**。

- 2G 是最低可跑配置，需要配合 Stage 2 的 2G swap；
- AI/RAG 场景更推荐 **2 核 4G**，内存更稳；
- 价格和地域以购买页为准（常有活动价，不要照抄旧价格）。

### 1.2 域名（可选）

- 有域名：简历上是 `https://你的域名/app/`，观感最好；
- 无域名：用 `http://服务器IP/app/`，浏览器会显示“不安全”；
- 境外节点（韩国/香港/新加坡/日本）通常不需要 ICP 备案；大陆节点绑定域名走 80/443 通常需要备案。

DNS：

- 必须：`@`（根域名）A 记录 → 服务器公网 IP；
- 可选：`www` A 记录 → 同一 IP。**没有配 `www` 就不要在 certbot 命令里加 `-d www.你的域名`。**

### 1.3 安全组 / 防火墙

云控制台安全组放行：

- 22/tcp（SSH，最好限制来源 IP）
- 80/tcp
- 443/tcp（要上 HTTPS 时）
- **不要**放行 8080、3306

## Stage 2 · 服务器初始化

```bash
# 1. 系统更新
sudo apt update && sudo apt upgrade -y

# 2. 时区（订单时间、AI 统计都依赖）
sudo timedatectl set-timezone Asia/Shanghai

# 3. 2G swap（容器构建/运行的内存保险丝）
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h

# 4. 基础工具
sudo apt install -y curl git unzip htop

# 5. 主机防火墙（与云安全组是两层，都要配）
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```

## Stage 4 · 本地构建、上传、启动

> 这一步在**你自己的电脑**上做，不要在 2G 服务器上跑 `npm ci + mvn package`。

### 4.1 发布脚本里三个已经处理好的坑（别改回去）

`deploy/scripts/local-release.sh` 里这三处是踩过坑之后写的，改动前先看理由：

1. **`bash ./mvnw`，不是 `./mvnw`** —— `backend/mvnw` 在 Git 里的模式是 `100644`（没有可执行位），Linux/CI 上直接执行会 `Permission denied`。用 `bash` 调用可绕过。
2. **`scp` 那行不加 `MSYS_NO_PATHCONV=1`** —— Git Bash 需要把本地路径 `/c/Users/...` 自动转换成 `C:/Users/...`，原生 `scp.exe` 才认得。禁用转换后它会去找 `C:\c\Users\...`，直接 `No such file or directory`。远端路径带 `host:` 前缀，MSYS 本来就不会转换，不需要干预。
3. **服务器端会调 `check-env.sh`** —— 拒绝 `ChangeMe` / `请替换` / 假 key。不要为了“先跑起来”绕过它。

### 4.2 一键发布

在 worktree 根目录、Git Bash 里执行：

```bash
cd /c/Users/25136/WorkBuddy/Worktrees/darunfa/feature-vue-admin-0781f852
bash deploy/scripts/local-release.sh root@你的服务器IP
```

脚本会：

1. `npm run build:backend` → 前端进 `backend/src/main/resources/static/app`
2. `bash ./mvnw -DskipTests package` → fat jar
3. `scp` 上传到服务器 `deploy/dist/app.jar`
4. 服务器执行 `docker compose -f docker-compose.local.yml up -d --force-recreate app`
   （jar 通过 `./dist:/app/dist:ro` 挂载进容器，换版本只需重启，不重建镜像）

### 4.3 分步手动（可选，等价）

```bash
# 本地
cd frontend && npm run build:backend && cd ..
cd backend && bash ./mvnw -DskipTests package && cd ..
mkdir -p deploy/dist
cp backend/target/backend-0.0.1-SNAPSHOT.jar deploy/dist/app.jar

# 先建远端目录，否则 scp 会 No such file or directory
ssh root@你的服务器IP "mkdir -p /opt/darunfa/deploy/dist"
scp deploy/dist/app.jar root@你的服务器IP:/opt/darunfa/deploy/dist/app.jar

# 服务器
cd /opt/darunfa/deploy
docker compose -f docker-compose.local.yml up -d --force-recreate app
```

> 首次部署（镜像还不存在）时，compose 会自动构建一次。
> 改了 `Dockerfile.runtime` 才需要手动 `docker compose -f docker-compose.local.yml build app`。

### 4.4 确认启动

```bash
cd /opt/darunfa/deploy
docker compose -f docker-compose.local.yml ps
docker compose -f docker-compose.local.yml logs --tail=80 app
```

期望：app `running`，mysql `healthy`；日志能看到 `HikariPool-1 - Start completed`、`Tomcat started on port 8080`、`Started BackendApplication`。

**统一规则**：2G 路径的所有 compose 命令都带 `-f docker-compose.local.yml`，包括 `ps/logs/exec/down/up`。默认的 `docker-compose.yml` 是服务器源码构建，2G 不要用。

### 4.5 本机验证

```bash
curl -I  http://127.0.0.1:8080/login.html          # 200
curl -I  http://127.0.0.1:8080/app/                # 302 Location: /app/index.html
curl -IL http://127.0.0.1:8080/app/                # 跟随重定向后 200
curl -s  http://127.0.0.1:8080/api/ping            # {"status":"ok"}
```

登录：

```bash
curl -s http://127.0.0.1:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | head -c 300
```

返回带 `token` 的 JSON 说明应用 + 数据库 + 鉴权链路通了。

### 4.6 首次启动后改 admin 密码

种子数据里已有 `admin`，`DataInitializer.initAdmin()` 会跳过，所以 `.env` 的 `ADMIN_PASSWORD` **不会覆盖**种子里的 `admin123`。首次启动后执行：

```bash
TOKEN=$(curl -s http://127.0.0.1:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' \
  | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')

curl -X PUT http://127.0.0.1:8080/api/user/password \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"oldPassword":"admin123","newPassword":"你的强口令"}'
```

之后：

- **公开演示用 `opsuser / admin123`（运营视角）**，不要把 admin 口令写进简历；
- 若坚持公开 admin，至少配合 7.4 每日重置，并明确写“演示环境，数据每日重置”。

> 如果你希望 `.env` 的 `ADMIN_PASSWORD` 生效，只能在种子导入后、应用启动前删掉 `users` 里的 admin 行；这比直接改密更绕，不推荐。

## Stage 5 · Nginx + 访问入口

### 5.1 安装 Nginx 与 Certbot

```bash
sudo apt install -y nginx
sudo apt install -y certbot python3-certbot-nginx   # 纯 IP 方案可不装
sudo systemctl enable --now nginx
```

### 5.2 配站点

**方案 A（有域名）**

```bash
sudo cp /opt/darunfa/deploy/nginx/darunfa.conf /etc/nginx/sites-available/darunfa.conf
sudo cp /opt/darunfa/deploy/nginx/ai-on.inc /etc/nginx/darunfa-ai.inc
sudo sed -i 's/your-domain.com/你的域名/g' /etc/nginx/sites-available/darunfa.conf
sudo ln -sf /etc/nginx/sites-available/darunfa.conf /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
# ⚠️ 首次启用站点必须 restart，不能 reload：
#    配置里有 listen 80 default_server（darunfa-ip.conf）或新增 server 块，
#    这类「监听套接字属性」的变更 reload 不一定完整生效，
#    症状就是 /api/ping 通、/app/ 却返回 nginx 自己的 404。
sudo systemctl restart nginx
```

**方案 B（纯 IP）**

```bash
sudo cp /opt/darunfa/deploy/nginx/darunfa-ip.conf /etc/nginx/sites-available/darunfa.conf
sudo cp /opt/darunfa/deploy/nginx/ai-on.inc /etc/nginx/darunfa-ai.inc
sudo ln -sf /etc/nginx/sites-available/darunfa.conf /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl restart nginx     # 同方案 A：首次启用用 restart
```

验证（`/app/` 在 Spring 侧是 302，跟随后才是 200）：

```bash
curl -IL http://你的域名/app/        # 方案 A，最终 200
curl -IL http://服务器公网IP/app/    # 方案 B，最终 200
```

> 如果这一步不通，先别签证书。排查顺序：DNS → 安全组 80 → `ufw status` → `curl -IL http://127.0.0.1:8080/login.html` → `nginx -t`。

### 5.3 签 HTTPS（仅方案 A）

只签根域名：

```bash
certbot --nginx -d 你的域名 \
  --agree-tos -m 你的邮箱 --redirect --non-interactive
```

只有当你已经给 `www` 配了 A 记录，才加：

```bash
certbot --nginx -d 你的域名 -d www.你的域名 \
  --agree-tos -m 你的邮箱 --redirect --non-interactive
```

验证续期：

```bash
curl -IL https://你的域名/app/
certbot renew --dry-run
```

> Let's Encrypt 必须校验域名所有权，纯 IP 签不了证书；自签证书浏览器会红字警告，不如先用 HTTP + 域名。

### 5.4 最终访问路径

| 方案 A（有域名） | 方案 B（纯 IP） | 内容 |
|---|---|---|
| `https://你的域名/` | `http://服务器IP/` | 302 到 `/app/`（由 Nginx 配置决定） |
| `https://你的域名/app/` | `http://服务器IP/app/` | **Vue 3 新后台（简历主推）** |
| `https://你的域名/admin.html` | `http://服务器IP/admin.html` | 旧版单文件后台 |
| `https://你的域名/login.html` | `http://服务器IP/login.html` | 旧版登录页 |

> 直连 8080 时 `/` 由 Spring `HomeController` 跳到 `/login.html`；通过 Nginx 时 `/` 由 Nginx 跳到 `/app/`。两者都正常，不要混淆。

### 5.5 建议加的安全头（可选）

在 Nginx 站点配置加：

```nginx
add_header X-Robots-Tag "noindex, nofollow" always;
```

同域部署不需要 CORS；如果以后前后端分域，再把后端 `allowedOriginPatterns("*")` 收敛为明确域名。

### 5.6 AI 接口限流（推荐）

`/api/chat`、`/api/ai/**` 在后端是公开路径，任何人拿到域名都能调，可能刷 DeepSeek 额度。

`deploy/nginx/darunfa.conf` / `darunfa-ip.conf` 已在文件顶部内置：

```nginx
limit_req_zone $binary_remote_addr zone=ai:10m rate=10r/m;
```

并在站点里加了 AI location（`include /etc/nginx/darunfa-ai.inc;` 是访问开关）：

```nginx
location ~ ^/api/(chat|ai) {
    include /etc/nginx/darunfa-ai.inc;
    limit_req zone=ai burst=5 nodelay;
    limit_req_status 429;
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 180s;
}
```

> `limit_req_zone` 只能在 `http` 上下文出现一次；站点配置已包含它，不要再往 `/etc/nginx/nginx.conf` 重复加，否则会报 duplicate zone。
> 两套站点配置二选一启用，不要同时启用，否则也会重复定义。

日常开关（Nginx 层，不改后端代码）：

```bash
sudo bash deploy/scripts/toggle-ai.sh off   # /api/chat、/api/ai/** 返回 403
sudo bash deploy/scripts/toggle-ai.sh on    # 恢复访问（仍受上面的限流约束）
```

如果只是静态展示，不想承担 AI 成本，直接 `off`；面试前再 `on`。

## 附录 A · 2 核 2G 机器说明

### A.1 已内置的调优

`deploy/docker-compose.yml` 与 `.local.yml` 里：

- MySQL：`--innodb-buffer-pool-size=192M`、`--performance-schema=OFF`、`--max-connections=50`
- 应用：`JAVA_OPTS="-Xms128m -Xmx640m -XX:+UseSerialGC -Duser.timezone=Asia/Shanghai"`

> 2G 能跑，但 AI/RAG 场景偏紧。验收时用 `docker stats --no-stream` 和 `free -h` 观察；如果 app 长期贴 640M 且 swap 持续读写，升级 4G 或把 `-Xmx` 调到 768m 观察。

### A.2 不要在服务器上构建

2G 跑 `npm ci + vite build + mvn package` 峰值会超过 2G，容易被 OOM Killer 打断。所以用本地构建通道：

```bash
bash deploy/scripts/local-release.sh root@你的服务器IP
```

### A.3 两套编排的区别

| 文件 | app 镜像 | 适用 |
|---|---|---|
| `docker-compose.yml` | 服务器从源码构建（Node + Maven） | 4G 以上 / CI |
| `docker-compose.local.yml` | COPY 本地已打好的 jar（`Dockerfile.runtime`） | **2 核 2G（本项目）** |

### A.4 改完代码怎么更新

- 只改 Java/前端：跑 `local-release.sh`，服务器不用 `git pull`（前端已在 jar 里）；
- 改 compose/nginx/sql/scripts：服务器 `git pull` 后再执行对应 compose 命令。

### A.5 内存不够排查

```bash
docker stats --no-stream
free -h
```

app 长期贴上限、swap 持续读写 → 升 4G，或关闭 RAG/AI 功能。

## 附录 B · 常见故障速查

| 现象 | 大概率原因 | 怎么查 / 怎么修 |
|---|---|---|
| 浏览器 502 | app 容器没起来/崩了 | `docker compose -f docker-compose.local.yml ps`；`logs --tail=100 app` |
| 容器启动几秒退出 | `.env` 缺值 或 MySQL 没 healthy | 日志看 `Could not resolve placeholder` / `Communications link failure`；先检查 `.env` 占位符 |
| 页面空白、js/css 404 | base 路径不对 | 本地 `grep -E 'src=|href=' backend/.../static/app/index.html`，必须以 `/app/assets/` 开头；出现 `C:/` 说明用了旧构建命令 |
| `/app/` 是 Spring 404 | 前端没打进 jar | **不要**用 `ls /app` 判断；用 `jar tf backend/target/backend-0.0.1-SNAPSHOT.jar \| grep 'static/app/index.html'` |
| `/api/ping` 通但 `/app/` 是 **nginx 自己的 404** | 站点配置只 reload 没 restart | 判断依据：404 的 `Server` 头带版本号（`nginx/1.24.0`）、`Content-Length: 162`。执行 `systemctl restart nginx`；首次启用含 `listen ... default_server` 的配置必须 restart |
| 中文乱码 | 字符集 | MySQL 参数 `--character-set-server=utf8mb4`、`--collation-server=utf8mb4_0900_ai_ci`；连接串 `characterEncoding=utf8` |
| AI 接口 401 | DeepSeek key 错/过期 | `docker compose -f docker-compose.local.yml exec app sh -c 'echo $DEEPSEEK_API_KEY'` 确认注入的是新 key |
| AI 504/超时 | Nginx 超时太短 | 站点配置 `proxy_read_timeout 180s`，确认没被别的 location 覆盖 |
| AI 余额不足 | DeepSeek 没钱 | 充值；说明费用护栏生效 |
| 首次 AI 很慢 | RAG 模型首次加载 | 正常，之后常驻内存 |
| `docker compose build` 卡住 | 拉依赖慢 | 换镜像源，或走本地构建上传 jar（附录 A.2） |
| 域名打不开但 IP 能开 | DNS/安全组 | `ping 域名`；云安全组 80/443；`ufw status` |
| certbot challenge 失败 | 80 被占/被拦/域名未解析 | `systemctl status nginx`、安全组 80、DNS；有 `www` 才加 `-d www` |
| MySQL 数据没了 | 用了 `docker compose down -v` | `-v` 会删具名卷，不可逆；重置前先备份 |
