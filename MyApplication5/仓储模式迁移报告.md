# MyApplication5 仓储模式（Repository 模式）迁移报告

执行日期：2026-09-04

---

## 一、目标

在已完成「后端代码移除」的基础上，彻底解耦 UI 层与 `AppDatabase`：

- UI 层（Activity / Fragment）不再直接 `AppDatabase.getInstance(...)` 调用数据访问。
- 改为通过 `RepositoryProvider` 服务定位器注入领域仓储接口。
- 订单状态常量改用 `entity/OrderStatus`，避免 UI 直接依赖 `db.AppDatabase` 里的常量。

这样，后续接入真实后端（`backend/` 目录的 Spring Boot）时，只需替换 `RepositoryProvider` 的装配逻辑，UI 层代码无需改动。

---

## 二、新增的仓储层（此前已就绪）

| 文件 | 说明 |
|---|---|
| `data/RepositoryProvider.java` | 服务定位器，`getInstance(context).user()/product()/review()/cart()/order()/browseHistory()` |
| `data/UserRepository.java` 等 6 个接口 | 用户 / 商品 / 评论 / 购物车 / 订单 / 浏览历史 领域接口 |
| `data/SqliteDataRepository.java` | 唯一实现，1:1 委托给 `AppDatabase`（迁移期行为完全一致） |
| `entity/OrderStatus.java` | 订单状态常量（值已与 `AppDatabase` 原始常量逐一核对一致） |

## 四、关键迁移点

### 1. ProductDetailsActivity 的领域拆分

原单个 `productDatabase` 字段承担了三类职责，迁移时拆分为三个仓储：

| 原调用 | 迁移后 |
|---|---|
| `productDatabase.getProductById(...)` / `updateStock(...)` | `productRepository` |
| `productDatabase.hasReviewed(...)` / `getReviewsByProduct(...)` / `getReviewCount(...)` / `getAverageRating(...)` / `addReview(...)` / `addReviewReply(...)` | `reviewRepository` |
| `productDatabase.addBrowseHistory(...)` | `browseHistoryRepository` |

### 2. 订单状态常量替换

`AppDatabase.STATUS_PENDING_SHIP / STATUS_PENDING_RECEIVE / STATUS_PENDING_REVIEW / STATUS_RETURNED`
→ `OrderStatus.STATUS_PENDING_SHIP / ...`（字符串值一致，行为不变）。

### 3. 字段命名规范

原 `xxxDatabase` 字段统一改为语义化 `xxxRepository`（如 `carDatabase` → `carRepository`），与仓储模式命名一致。
